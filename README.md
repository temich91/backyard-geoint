# backyard-geoint
Проект в рамках курса "Распознавание образов"

**Задача**: поиск локации по фотографии в пределах одного города (Visual Place Recognition).

**Входные данные**: уличные фотографии из Mapillary с метками геолокации.

## Основной протокол: вариант Б (пространственный)

Модель обучается и проверяется на разных территориях одного города. Вариант А
(те же места, другие поездки) остаётся только дополнительным экспериментом.

| Этап | Данные | Назначение |
|---|---|---|
| Обучение | `data/city_train/views_spatial/train.csv` | Изменение весов модели |
| Валидация | `data/city_train/views_spatial/val_database.csv` и `val_queries.csv` | Расчёт Recall, выбор чекпоинта и параметров |
| Финальный тест | `data/district/views/database.csv` и `queries.csv` | Однократная итоговая оценка после настройки |

Правила разделения:
- Тестовый район исключается из обучающей территории вместе с буфером 100 м.
- Оставшаяся территория делится на блоки 500×500 м: примерно 85% для train и 15% для val.
  Фото ближе 50 м к границе между train и val исключаются.
- База и запросы внутри каждой проверочной территории берутся из разных поездок.
  Географически они должны пересекаться: у запроса должен быть правильный ответ в базе.
- Фото тестового района, включая его `train.csv` и `val.csv`, не используются для обучения,
  выбора модели или настройки параметров. Веса из эксперимента А на этом районе также
  нельзя использовать как начальные для основного эксперимента Б.
- Добавление проверочных фото в FAISS после обучения не меняет веса модели и допустимо.

Размер класса остаётся 50×50 м + направление камеры; блоки 500×500 м нужны для сплита,
а не для определения классов. Классы train и val не пересекаются.

Подготовка данных и команды: [src/data/README.md](src/data/README.md).
Скрипт обучения по умолчанию читает `data/city_train/views_spatial/train.csv`:

```bash
python src/training/train.py --epochs 10 --batch-places 16
```

**Текущее ограничение:** обучение пока не считает валидационный Recall и выбирает лучший
чекпоинт по обучающему loss. Валидационный поиск и выбор модели по Recall ещё нужно реализовать;
тестовый район для этого не используется.

## Поиск через FAISS

Реализованы точный косинусный поиск, сохранение/загрузка индекса и CLI
`python -m src.search build|query`. Модуль принимает готовые векторы `.npy` и CSV базы
в одинаковом порядке; возвращает топ-k снимков с координатами. Извлечение векторов
из фотографий подключается отдельно, без зависимости поискового модуля от PyTorch.

**Контракт с модулем извлечения признаков, Python API и команды для варианта Б:**
[src/search/README.md](src/search/README.md).

## Пайплайн

1) **Сбор и предобработка датасета**
   * Загрузка уличных фотографий с заданной пространственной плотностью
   * Разрешение дубликатов, создание собственных ID (если надо)
   * Пространственный сплит (Spatial Split) на train/val/test без географического перекрытия (во избежание утечки данных)
   * Создание класса датасета для последующей работы в PyTorch

2) **Создание модели для распознавания локации**
   * Реализация архитектуры MixVPR на основе ResNet50 на PyTorch
   * Извлечение эмбеддингов для тренировочных данных

3) **Реализация векторного поиска в FAISS**
   * Построение индекса по эмбеддингам
   * Привязка метаданных: сопоставление внутренних ID векторов в индексе с метаинформацией (GPS-координаты `lat`, `lon`, ID кадра)
   * Консольный интерфейс: поиск топ-$k$ кандидатов по готовому вектору, вывод координат и косинусного сходства; приём фотографии подключается через модуль извлечения признаков

4) **Тестирование качества поиска и критерии успеха**
   * **Критерий истинности (Ground Truth)**: предсказание считается верным, если найденный кандидат находится в пределах радиуса $r \le 50$ метров от истинной точки съемки
   * **Ключевые метрики**:
     * `Recall@k` ($k \in \{1, 5, 10\}$) — доля запросов, для которых хотя бы один из топ-$k$ кандидатов попал в радиус $r$
     * Средняя и медианная ошибка локализации (расстояние в метрах между истинной точкой и ближайшим предсказанным кандидатом)
   * Итоговая проверка качества на отложенной тестовой выборке

## Структура проекта

```text
├── data/
│   ├── city_train/          # Обучающая территория; views_spatial/ с train и val
│   ├── district/            # Отдельный тестовый район; views/ с базой и запросами
│   └── raw/                 # Каталог загрузчика по умолчанию; для Б явно задаём --out
├── configs/                 # Конфигурационные файлы (параметры модели, обучения, путей)
├── src/
│   ├── data/                # Загрузка Mapillary, подготовка CSV, гео-сплит, PyTorch Dataset
│   ├── models/              # Архитектура MixVPR (бэкбон + Feature Mixer)
│   ├── training/            # Trainer, функции потерь, сэмплирование пар/триплетов (hard-negative mining)
│   ├── search/              # Построение и сериализация индекса FAISS, модуль векторного поиска
│   ├── utils/               # Вспомогательные скрипты
│   └── eval/                # Расчет Recall@k, метрик расстояния и валидация
├── scripts/                 # CLI-скрипты запуска этапов пайплайна (сбор, индексация, поиск, оценка)
├── pyproject.toml           # Зависимости проекта (PEP 621) и конфигурация инструментов
├── README.md
└── .gitignore               # Для крупных файлов данных, чекпоинтов моделей и faiss-индексов
```

## Рабочий процесс
* **`main`** — релизная стабильная версия
* **`dev`** — основная ветка для интеграции отдельных задач
* **`feature/<name>`** — ветки для отдельных задач (ответвляются от `dev`)
* **`fix/<issue>`** — исправление ошибок

Файлы данных (`data/`, включая `city_train/` и `district/`), обученные веса (\*.pth, \*.pt) и файлы индексов (\*.faiss)
не коммитятся в Git и обязательно добавляются в .gitignore.

Кросс-ревью: по готовности задачи открывается pull request в ветку dev.

## Установка и развертывание

Для быстрого и воспроизводимого управления зависимостями в проекте используется [**uv**](https://github.com/astral-sh/uv).

### Требования
* Установленный **uv** (или стандартный `pip`)

---

### Быстрый старт с `uv`

1. **Клонирование репозитория:**
   ```bash
   git clone https://github.com/temich91/backyard-geoint.git
   cd backyard-geoint
   ```
   
2. **Создание виртуального окружения:**
   ```bash
   uv venv --python 3.12
   ```

3. **Активация окружения:**
   * **Windows (PowerShell):**
     ```powershell
     .venv\Scripts\Activate.ps1
     ```
   * **Linux / macOS:**
     ```bash
     source .venv/bin/activate
     ```

4. **Установка проекта и зависимостей:**
   ```bash
   uv pip install -e .
   ```

**Поддержка GPU (CUDA):**
По умолчанию устанавливается базовая версия для CPU. Для ускорения на видеокартах NVIDIA установите PyTorch с поддержкой CUDA:
```bash
uv pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
```

---

### Альтернатива: Стандартный `pip`
```bash
python3.12 -m venv .venv
# Активация (.venv\Scripts\Activate.ps1 на Windows или source .venv/bin/activate на Linux)
pip install --upgrade pip
pip install -e ".[dev]"
```
